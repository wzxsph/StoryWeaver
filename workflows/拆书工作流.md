# 拆书/导入工作流

## 触发条件

用户要求导入现有小说、存稿、平台导出的正文，或执行 `/storyweaver:import --path <file-or-dir>`。

## 输入

- `.txt` 或 `.md` 正文文件
- 包含多个 `.txt`/`.md` 章节文件的目录
- 项目标题、作者、起始章节编号等可选参数

## 工作流程

### Step 1: 确定性导入

优先执行：

```bash
node "${CLAUDE_PLUGIN_ROOT}/tools/import-manuscript.mjs" "${CLAUDE_PROJECT_DIR}" --input "<path>"
```

导入器负责：

1. 识别 `第一章`、`第12章`、`Chapter 12` 等常见标题。
2. 分割章节内容。
3. 保存 `chapters/chapter_{N}.txt`。
4. 生成 `state/chapters/chapter_{N}.json` 章节契约。
5. 生成 `state/chapters/chapter_{N}/brief.json` 章节上下文包。
6. 写入 `state/metadata/import_report.json`。
7. 重建 `state/metadata/index.json`。

### Step 2: 状态提取

对导入章节逐章执行 state-extractor：

- 先运行 `/storyweaver:extract --chapter N --apply` 生成可审计提取报告。
- 提取角色、物品、场景、组织、概念。
- 提取时间线事件、情节线和关系。
- 将新增实体写入对应 `state/{type}/{id}.json`。
- 更新 `state/chapters/chapter_{N}.json.state_delta`。

导入器生成的章节契约是占位契约，不能当作最终 canon；提取后需要补全 `chapter_goal`、`conflict_axis`、`turning_point` 和 `summary`。

### Step 3: 一致性校验

对导入范围执行：

```bash
/storyweaver:verify --chapter N --scope all
```

审阅报告写入 `state/chapters/chapter_{N}/review.json`。发现 critical 问题时先修正文稿或状态，再进入下一章。

随后运行：

```bash
/storyweaver:queue
/storyweaver:gate --chapter N
```

导入章节只有在 gate 不 blocked 时，才可被标记为 `verified` 或用于自动循环的下一章依据。

### Step 4: 大纲回填

基于导入报告、章节契约和状态提取结果生成：

- `state/outline/outline.json`
- `state/outline/volume_{N}.json`
- `state/outline/chapter_{N}.json`

## 输出

1. `chapters/chapter_{N}.txt`：保留原始导入正文。
2. `state/chapters/chapter_{N}.json`：章节契约与状态增量。
3. `state/chapters/chapter_{N}/brief.json`：章节上下文包。
4. `state/chapters/chapter_{N}/extraction.json`：状态提取报告。
5. `state/chapters/chapter_{N}/gate.json`：章节闸门报告。
6. `state/metadata/import_report.json`：导入报告。
7. `state/metadata/index.json`：项目导航索引。
8. `state/**/{id}.json`：提取后的实体状态。

## 约束

- 原始正文必须保留，不允许在导入阶段自动改写。
- 导入阶段只做机械切章和占位契约，不凭空发明角色设定。
- 状态提取后的 JSON 必须通过 `tools/validate-state-schemas.mjs`。
- `state/metadata/index.json` 可重建，不作为 canon 事实来源。
